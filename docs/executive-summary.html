Executive summary: exactly how a submission is made

Current GEMSDOE82 file: DO NOT SUBMIT (negative holdout verdict, see home). The steps below are the complete, correct portal procedure for any future cleared file.
  1. Download the cleared -zeros.tif (or its .zip) from the top of the home page. The zeros file is all-finite with no nodata tag, so the portal error “Predicted values must be in range [0, 1]” cannot trigger: every one of 12,279,160 cells was re-read from disk and verified in [0,1] (that error is caused by the −3.4e38 sentinel or a sentinel nodata tag — both absent here).
  2. Optionally verify bytes: sha256sum must match the receipt next to the download link, and python scripts/validate_submission.py <file> zeros must print all_passed: true (CRS EPSG:32611, shape 3730×3292, transform, float32, no NaN inside footprint, range [0,1], 0 on-catalogue).
  3. Sign in at DrivenData → DOE GEMS Prize → Submit. Choose the single .tif (or a .zip containing exactly one GeoTIFF).
  4. Unique name: GEMSDOE82-BLINDSTEP-LINE-37654. Note field (≤140 chars used here): GEMSDOE82 blind-step line 37,654 dots; HOLDOUT-DTI 0.0745 n.s. vs random; DO NOT SUBMIT negative lane
  5. Submit once. Record the portal's returned score in the repo as ORGANIZER-CONFIRMED only with that receipt; never relabel a projection as a score. Weekly cap is shown on the submission page — promotion to a slot is a separate selector decision; this repo used 0 slots.

Format contract (organizer): single-band float32 GeoTIFF, EPSG:32611, 100 m, same bounds/transform as training data, values in [0,1], null/NaN outside — problem description.
