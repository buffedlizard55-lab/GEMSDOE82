Likely meaning of “zeros”

The public build metadata describes a sparse, nonzero candidate emission whose name ends in “zeros.” In that repository’s naming, the suffix refers to an outside-fill convention, not an all-zero prediction raster. This is a claim from the owner-maintained manifest; it has not been recomputed from the TIFF bytes here.

Plausible mechanism, not a proven cause

The build description says the candidate was formed by removing pixels close to the mapped catalogue from an earlier emission. If removed pixels would otherwise be false positives, this can improve precision while retaining predictions farther from mapped faults. It can also hurt recall if hidden faults are near the public catalogue. One reported score cannot distinguish those possibilities, public-test luck, leakage, or leaderboard overfitting.

The official distance-weighted Tversky metric rewards predictions near hidden fault pixels and penalizes unmatched prediction mass. That makes distance-aware pruning plausible, but only the required blocked holdout with a confidence interval can test the mechanism locally.
